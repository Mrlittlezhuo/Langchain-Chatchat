# Langchain-Chatchat 源码学习指南

> 适用代码快照：`master` 分支，提交 `49165d6a`，服务包版本 `0.3.1.3`  
> 制定日期：2026-08-20  
> 适用对象：有代码基础、熟悉 Linux，但刚开始系统学习 RAG 和 AI Agent 开发的开发者

## 1. 学习目标

这套计划不追求“把仓库每个文件读完”，而是让你沿着真实请求链路建立可验证的系统认知。完成后，你应该能够：

1. 独立配置并运行 Langchain-Chatchat、模型服务和默认知识库。
2. 解释普通对话、知识库问答、文件问答和 Agent 对话的完整调用链。
3. 理解文档解析、分块、Embedding、混合检索、重排和生成之间的关系。
4. 理解 Agent 的工具注册、参数生成、工具执行、Observation 回传和终止逻辑。
5. 新增一个带参数校验、异常处理和测试的自定义工具。
6. 使用 FastAPI/OpenAI 兼容接口调用系统，并读懂 SSE 流式响应。
7. 为一个小型 RAG + Agent 应用建立基本评测集，分析失败原因。

完成计划后，你的目标水平不是“会点击 WebUI”，而是：

```text
能够从一个 API 请求出发找到关键源码，
能够说明每一层的输入和输出，
能够修改一个模块并用测试或实验验证修改。
```

## 2. 暂不作为主线的内容

以下内容并非不重要，而是不应在入门阶段分散注意力：

- 大模型预训练、微调、量化和 CUDA 内核。
- 同时研究所有模型平台；主线只选一个 OpenAI 兼容模型服务。
- 同时研究 FAISS、Milvus、PGVector、Elasticsearch 等所有向量库；先吃透 FAISS。
- Streamlit 的复杂视觉定制。
- 仓库中名称包含 `stale` 的旧入口。
- 一开始就升级 LangChain 或重构整个 Agent 框架。

## 3. 建议投入时间

推荐采用标准节奏：**10 周，每周 8～10 小时，总计约 90 小时**。

| 节奏 | 每周投入 | 完成周期 | 适用情况 |
|---|---:|---:|---|
| 轻量 | 5～6 小时 | 14～16 周 | 工作日时间较少 |
| 标准（推荐） | 8～10 小时 | 10 周 | 能稳定学习 5 天 |
| 集中 | 14～16 小时 | 6～7 周 | 有连续完整时间 |

标准学习日建议安排 90～120 分钟：

```text
15 分钟：复习上次结论和未解决问题
25 分钟：学习一个必要概念
45 分钟：跟踪源码或断点调试
25 分钟：做一个小实验
10 分钟：记录证据、结论和新问题
```

每周至少 60% 的时间用于运行、调试、修改和验证代码。阅读文章或观看视频不能替代动手实验。

## 5. 项目技术栈速览

| 层次 | 当前项目技术 |
|---|---|
| 主语言 | Python 3.10～3.11 |
| CLI | Click |
| API | FastAPI + Uvicorn |
| 流式协议 | SSE (`sse-starlette`) |
| WebUI | Streamlit |
| Agent/RAG 框架 | LangChain 0.1.x |
| 模型协议 | OpenAI 兼容 API |
| 默认向量库 | FAISS |
| 关键词检索 | BM25 + jieba |
| 结构化数据库 | SQLAlchemy，默认 SQLite |
| 配置 | Pydantic Settings + YAML |
| 依赖管理 | Poetry |
| 测试 | pytest + pytest-asyncio |
| 部署 | Docker / Docker Compose |

当前服务包真实依赖和 Python 版本以 [`../../libs/chatchat-server/pyproject.toml`](../../libs/chatchat-server/pyproject.toml) 为准，不要只依据根目录的占位 `pyproject.toml` 或旧教程。

        ┌──────────┼──────────┐
        ▼          ▼          ▼

                   │ HTTP

需要牢牢记住：**Chatchat 是应用与编排层，不应与模型推理服务混为一谈。** 0.3.x 架构下，模型一般在独立服务中运行，Chatchat 通过 OpenAI 兼容 HTTP API 调用模型。

## 7. 学习方法

### 7.1 以纵向链路为单位阅读

不要按照目录从上到下阅读。每次只选择一个问题，例如：

- `chatchat start -a` 如何启动两个服务？
- `/chat/kb_chat` 如何获得文档并调用模型？
- 一个工具如何被注册并进入 Agent 可用工具列表？
- Agent 如何把工具结果重新交给 LLM？

然后只追踪解决该问题需要的调用链。

### 7.2 每个函数只记录四项

```text
输入：参数与依赖状态
输出：返回值、生成器或副作用
调用：它调用了哪些关键模块
异常：失败如何传播或被转换
```

### 7.3 使用证据而不是印象

“我大概懂了”不算完成。以下任意一种才算有效证据：

- 画出调用链并标出真实文件和函数名。
- 用断点或日志验证调用顺序。
- 修改参数后观察到可解释的结果变化。
- 编写测试复现行为。
- 不看代码，向别人解释输入、状态变化和输出。

### 7.4 建立问题停车场

遇到与当前链路无关的问题，记录到学习日志的“停车场”，不要立即展开。例如阅读 RAG 时遇到 MCP，只记录链接，等 Agent/MCP 阶段再处理。

## 8. 版本与源码阅读注意事项

1. 当前主服务包锁定在 LangChain 0.1.x，网上大量 LangChain 0.2/0.3/1.x 示例的 API 可能不同。
2. 优先阅读 `libs/chatchat-server`；根目录只是项目聚合层。
3. `chatchat` 是应用层，`langchain_chatchat` 是 LangChain 扩展与 Agent 实现层。
4. 名称包含 `_stale.py` 的文件是旧实现，不作为主线入口。
5. Docker Compose 中的镜像标签可能落后于本地源码；源码学习优先使用 Poetry 环境。
6. `chatchat kb -r`/`--recreate-vs` 会重建数据，执行前确认 `CHATCHAT_ROOT` 并备份重要数据。

## 10. 完成标准

满足以下条件才视为完成本计划：

- 能在 10 分钟内从 API 路由定位到模型调用入口。
- 能画出 RAG 入库和 RAG 查询两条不同链路。
- 能解释 FAISS 向量检索与 BM25 关键词检索为什么要组合。
- 能解释 `AgentAction`、Observation、`intermediate_steps`、`AgentFinish`。
- 能新增工具，并证明模型可以正确选择、不选择和错误处理该工具。
- 能完成至少 20 条固定问题的评测，并对失败进行分类。
- 能独立完成文档最后的结业项目。
