## 3. 本周需要回答的问题

### 3.1 为什么 Chatchat 和 Ollama 要分开？

Ollama 负责模型加载、GPU 推理和 OpenAI 兼容接口；Chatchat 负责 API、WebUI、知识库、检索、Prompt 和 Agent 编排。分离后：

- 更换模型时不必修改 Chatchat 业务逻辑。
- Chatchat 重启不会重新安装或下载模型。
- 可以分别判断故障位于模型层还是应用层。
- 后续可使用 Xinference 或其他 OpenAI 兼容服务替换 Ollama。

### 3.2 配置和数据保存在哪里？

```text
/home/lab239/chenzhuo/chatchat-study-data
├── basic_settings.yaml       # API、WebUI、数据库和绑定地址
├── kb_settings.yaml          # 分块、向量库、Top K 和阈值
├── model_settings.yaml       # 模型平台、LLM 和 Embedding
├── prompt_settings.yaml      # RAG 和其他 Prompt
├── tool_settings.yaml        # 工具配置
└── data
    ├── knowledge_base         # 原始文档、FAISS 索引和 SQLite
    ├── logs                   # 运行日志
    ├── media
    └── temp
```

源代码位于 Git 仓库，运行配置和知识库数据位于独立的 `CHATCHAT_ROOT`。这样可避免源码更新覆盖运行数据。

### 3.3 为什么必须先测试模型服务？

如果直接启动 Chatchat，出错时难以区分问题来自 Ollama、模型文件、GPU、网络还是 Chatchat 配置。本次先分别调用 Ollama 的 Generate 和 Embed API，再接入 Chatchat，使故障边界更清楚。

```text
本地电脑浏览器
    │
    ├── http://10.10.12.248:8501
    │        ↓
    │   Streamlit WebUI
    │
    └── http://10.10.12.248:7861
             ↓

             │
             ├── RAG 检索
             │     ├── SQLite: info.db
             │     └── FAISS: vector_store/bge-m3
             │
             └── http://127.0.0.1:11434/v1
                       ↓
                 Ollama
                 ├── qwen2:7b
                 └── bge-m3
```

| 端口 | 服务 | 绑定 | 设计原因 |
|---:|---|---|---|
| 11434 | Ollama | `127.0.0.1` | 仅供 Chatchat 本机调用，不直接暴露模型服务 |
| 7861 | FastAPI | `0.0.0.0` | 允许本地电脑访问 API 和文档 |
| 8501 | Streamlit | `0.0.0.0` | 允许本地电脑访问 WebUI |

`0.0.0.0` 是服务监听地址，不是浏览器地址。远程浏览器应使用服务器实际 IP `10.10.12.248`。

## 8. 失败案例与处理

### 8.1 Python 3.11 安装旧版 Pandas 失败

- **现象**：安装 `pandas-1.3.5` 时进入源码构建，出现 `ModuleNotFoundError: No module named 'pkg_resources'`。
- **失败层**：Python 与依赖版本兼容性。
- **根因**：项目锁定的 Pandas 过旧，对 Python 3.11 的轮子支持不完整。
- **处理**：将独立 Conda 环境调整为 Python 3.10.20。
- **验证**：源码包成功可编辑安装，`chatchat --help` 可正常执行。

### 8.2 Requests 依赖警告

- **现象**：`chardet 7.6.0` 不在 Requests 支持范围内。
- **处理**：安装 `chardet>=3.0.2,<6`，实际版本为 `5.2.0`。
- **验证**：Requests 2.32.5 可正常导入，相关版本警告消失。

### 8.3 WebUI 普通对话页面崩溃

- **现象**：出现 `UnboundLocalError: local variable 'use_mcp' referenced before assignment`。
- **失败层**：WebUI 控制流。
- **根因证据**：`use_mcp` 只在 `if use_agent:` 分支内赋值，但构建 `extra_body` 时无条件读取。
- **修复**：在条件分支前增加 `use_mcp = False`。
- **静态验证**：Python AST 语法检查和 `git diff --check` 均通过。
- **回归验证**：重启 WebUI 后页面恢复，Agent 关闭时普通对话成功。
- **记录决定**：经确认，该问题不写入长期“项目缺陷与优化清单”，仅保留在本周排障记录中。

## 10. 我现在可以不看代码解释

1. Chatchat 不是模型本身，它通过 OpenAI 兼容 API 调用 Ollama。
2. LLM 负责生成文本，Embedding 负责将文本转换为向量，两者不能互相替代。
3. `CHATCHAT_ROOT` 决定运行配置和数据位置，新终端中需要重新导出。
4. 知识库入库的核心过程是“加载文件 → 分块 → Embedding → 保存 FAISS 索引和元数据”。
5. SQLite 保存知识库、文件和文档块元数据，FAISS 保存用于相似度检索的向量索引。
6. `0.0.0.0` 用于服务监听，远程浏览器应使用服务器实际 IP。
7. 应分层测试 Ollama、API、WebUI 和 RAG，不能把所有异常都称为“模型问题”。
