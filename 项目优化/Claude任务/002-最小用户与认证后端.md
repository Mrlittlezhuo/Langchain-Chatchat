## 7. 设计约束

### 7.1 用户表与模型

物理表名使用 `user_account`，避免与数据库保留字 `user` 冲突。新增
`UserModel`，至少包含：

| 字段 | 约束 |
|---|---|
| `id` | `String(32)` 主键，服务端生成 UUID hex |
| `username` | `String(64)`，非空、唯一，只保存规范化小写值 |
| `display_name` | `String(100)`，非空 |
| `password_hash` | `String(255)`，非空，禁止在 repr/API 中出现 |
| `role` | `admin` / `user`，非空 |
| `status` | `active` / `disabled`，非空 |
| `must_change_password` | Boolean，非空 |
| `auth_version` | Integer，非空，初始为 1 |
| `create_time` | DateTime，非空 |
| `update_time` | DateTime，非空，修改时更新 |

约束：

- username 去除首尾空白后转小写，长度 3–64，只允许 ASCII
  `a-z`、`0-9`、`.`、`_`、`-`；
- username 不可修改；显示名称允许 Unicode；
- role/status 必须在允许集合内，数据库迁移尽量增加 CHECK 约束；
- API/CLI 对重复 username 给出明确冲突，不把数据库异常栈返回给客户端；
- Repository/service 核心接受显式 SQLAlchemy `Session`，测试不能绑定
  全局真实数据库。

### 7.2 v2 迁移

- 只在现有注册表末尾追加 v2，不修改已经发布的 v1；
- v2 只创建 `user_account` 及必要索引/约束，不创建默认账户；
- 空临时库从 v1→v2 按顺序升级；已有 v1 临时库只执行 v2；
- 迁移重复运行安全，失败不记录 v2；

### 7.3 密码安全

使用 Python 标准库 `hashlib.scrypt`，不要再包装快速通用哈希。参数固定为：

```text
N = 2^14
r = 8
p = 5
salt = 16 random bytes
derived key = 64 bytes
```

该组合是 OWASP 给出的最低等效 scrypt 配置之一，当前环境单次计算可离线
运行。参考：

- https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html
- https://docs.python.org/3/library/hashlib.html#hashlib.scrypt

存储格式必须自描述、可版本化，例如：

```text
scrypt$1$n=16384,r=8,p=5$<base64url-salt>$<base64url-digest>
```

要求：

- 盐使用 `secrets.token_bytes(16)` 或等价 CSPRNG，每个密码独立；
- 使用 `hmac.compare_digest` 比较；
- 格式错误、参数异常和超限输入安全返回验证失败，不向客户端泄漏异常；
- 密码允许 Unicode 和空格，不设置字符种类组合规则；
- 新密码最少 12 个字符，UTF-8 后最多 1024 bytes，禁止静默截断；
- hash/repr/日志/响应中不得出现明文密码；
- 未知用户名和错误密码返回相同状态与通用错误；未知用户路径执行固定
  dummy hash 验证，降低明显的用户名枚举时序差异。

### 7.4 JWT 与密钥

使用项目已有 `PyJWT`，只允许 `HS256`。签发/验证时：

- 从环境变量 `CHATCHAT_AUTH_SECRET` 读取密钥；
- 密钥缺失或 UTF-8 长度小于 32 bytes 时失败关闭：登录签发返回可操作的
  服务端配置错误，但绝不打印密钥；
- 不在源码、模板、测试快照或任务报告中提交真实密钥；
- Token 有效期固定 30 分钟；
- claims 至少包含 `sub`（user id）、`ver`（auth_version）、`iat`、
  `exp`、`iss=langchain-chatchat`；
- 解码时固定算法列表、校验 issuer 和必需 claims，不信任 Token 中的
  username/role/status；
- `get_current_user` 每次按 `sub` 查询数据库，并验证 active 和
  auth_version；
- 禁用、重置密码或用户自行修改密码时 `auth_version += 1`，使旧 Token
  立即失效；
- 过期、签名错误、用户不存在、禁用或版本不一致统一返回 401，并带
  `WWW-Authenticate: Bearer`；
- logout 是无服务端会话表的幂等接口，只通知客户端删除当前短期 Token，
  不虚构“服务端已撤销”；真正失效依靠过期或 auth_version 变化。

### 7.5 认证和管理 API

新增并注册：

```text
POST /auth/login
GET  /auth/me
POST /auth/logout
POST /auth/change-password

GET   /admin/users
POST  /admin/users
PATCH /admin/users/{user_id}/status
POST  /admin/users/{user_id}/reset-password
```

约束：

- login 使用 JSON username/password，成功返回 Bearer Token、过期秒数和
  脱敏用户信息；
- `/auth/me` 和 logout 要求 active 当前用户；
- change-password 必须验证旧密码，成功后清除
  `must_change_password` 并增加 auth_version；
- 提供可复用的 `get_current_user`、`require_admin`，以及供后续业务
  路由使用的“已完成强制改密”依赖；
- 管理接口只允许 admin；
- 创建用户由服务端生成 id，初始密码由管理员请求提供但不回显，
  `must_change_password=true`；
- reset-password 由管理员请求提供新临时密码，不生成/回显密码，
  设置 `must_change_password=true` 并增加 auth_version；
- 禁用用户增加 auth_version；重新启用仍保留已经增加的版本；
- 禁止管理员禁用自己，禁止操作导致系统没有 active admin；
- 用户列表和所有响应不得包含 password_hash、明文密码或 JWT 密钥；
- 重复 username 返回 409，目标不存在返回 404，权限不足返回 403，
  认证失败返回 401，输入校验错误返回 422；
- 本任务不把这些依赖挂到既有业务 Router，避免在 WebUI 登录能力完成前
  隐式改变全部现有接口。

### 7.6 首个管理员 CLI

在根 CLI 注册语义清楚的命令组，建议：

```text
chatchat users init-admin
```

要求：

- username/display name 可交互输入或使用非敏感选项；
- 密码必须通过 Click 隐藏输入并二次确认，禁止 password 命令行选项；
- 数据库不存在或尚未显式执行 `chatchat migrate upgrade` 时给出明确
  提示，不自动迁移；
- 已存在 admin 时拒绝再次执行；没有 admin 时才可创建；
- 不自动创建固定用户名、固定密码或随机但无人保存的密码；
- 成功输出仅包含 username/id 等非敏感信息；
- 导入 CLI 模块不连接或修改数据库。

### 7.7 分层与可测试性

- 密码、JWT、Repository/service、FastAPI 依赖、HTTP 路由和 CLI 职责分离；
- API 测试必须用依赖覆盖或显式 session 指向临时数据库；
- 不因导入 `server_app`、auth 路由或 CLI 而创建表/用户；
- 不捕获并吞掉编程错误；对预期业务错误映射稳定 HTTP/CLI 错误；
- 不在异常和日志中输出请求密码、Authorization header 或完整 Token。
