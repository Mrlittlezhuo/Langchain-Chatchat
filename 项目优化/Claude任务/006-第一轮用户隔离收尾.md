## 目标

完成以下结果：

1. **临时文件与聊天附件私有**
   - 临时文件对话、聊天图片及附件能识别上传用户；
   - 上传、使用、读取、下载和删除时校验当前用户；
   - 用户 A 不能通过替换 ID 使用或获取用户 B 的临时内容；
   - 临时内容不能混入永久公共知识库。

2. **补齐业务接口认证**
   - 聊天、RAG、临时文件、图片/附件及知识库业务接口只允许已登录且完成改密的用户访问；
   - 普通聊天、RAG、Agent 和反馈继续遵守已有会话所有权；
   - 不把模型、工具、MCP 或永久知识库改成用户私有。

3. **完成旧会话迁移**
   - 为仍无 owner 的旧会话提供明确的遗留用户归属；
   - 升级前后会话和消息数量不变；
   - 新会话不能再产生空 owner；
   - 不移动知识库目录，不重建公共向量索引；
   - 只在临时测试数据库验证，不操作真实数据库。

4. **保持公共知识库共享**
   - 所有登录用户看到并操作同一份永久知识库；
   - 页面明确提示“公共知识库修改会影响所有用户”；
   - 删除文件、重建或删除知识库前有确认；
   - 记录最小操作审计信息，采用项目内最简单可维护的实现即可。

5. **完成第一轮回归**
   - 覆盖 A/B 用户的会话、消息、反馈、临时文件和附件隔离；
   - 覆盖普通聊天、RAG、Agent 的用户归属；
   - 覆盖公共知识库仍然共享；
   - 覆盖旧数据升级不丢失；
   - 保持登录刷新、侧栏导航、历史会话恢复可用。

## Claude 执行报告

### 实现思路与修改范围（本轮）

本轮完成 006 的全部五个目标：临时文件/聊天附件私有化、补齐业务接口认证、旧会话归属迁移
（v5）、公共知识库共享与最小审计、第一轮回归。要点如下。

1. **临时文件（文件对话）属主隔离**
   - 新增进程内属主注册表 `chatchat/server/knowledge_base/temp_files.py`：
     `temp_id -> owner_id`，线程安全，与 `memo_faiss_pool` 同为进程级生命周期。
   - `upload_temp_docs`：上传时由服务端认证上下文（`require_password_changed`）写入属主；
     客户端无法指定 owner。
   - `search_temp_docs` / `file_chat`：统一加认证依赖 + 属主 404 守卫（非属主/不存在一律
     404，不泄露存在性），保证 A 无法检索/对话/删除/复用 B 的 `temp_id`。

2. **聊天图片/附件（OpenAI 兼容 `/v1/files`）属主隔离**（前几轮已落地，本轮核对并随测试固化）
   - `user_model.py` 增加 `OpenAIFileModel`（表 `openai_file`），注册到 `Base`。
   - `openai_routes.py` 的 `/v1/files` 各端点均要求认证，属主恒取服务端上下文；A 的列表
     为空、读取/下载/删除 B 的文件 404。
   - **v4 迁移**（`migrations.py`）：新增 `openai_file` 表，幂等、不动既有会话/消息/知识库。
     本轮修正了原 `_OPENAI_FILE_TABLE` 重复 `IF NOT EXISTS` 导致的 SQLite 语法错误
     （原 `apply_migrations` 会在迁移阶段抛异常，使依赖完整注册表的测试无法通过）。

3. **旧会话归属迁移（v5）**
   - `migrations.py` 追加 **v5 迁移** `_legacy_conversation_owner`：为仍无 `owner_id`
     的存量会话统一归属到一个明确的遗留用户 `__legacy__`（`role=user`、`status=active`、
     `must_change_password=1`、`auth_version=0`）。
   - 幂等：`conversation` 表或 `owner_id` 列不存在、或无 NULL 行时不新建用户；遗留用户
     已存在（按 `username`）时复用其 `id`。
   - 数据保留：只 `UPDATE conversation.owner_id`，不修改 `message` 行、不动知识库表，
     不移动公共知识库目录，不重建公共向量索引；升级前后会话与消息数量不变。
   - 新会话不再产生空 owner：`create_conversation` 与各 API 路由均恒取服务端认证上下文
     作为 `owner_id`，v5 仅处理存量 NULL 行。
   - 内置迁移注册表由 4 版增至 5 版；`test_db_migrate.py` 相应断言由 4 版改为 5 版
     （`latest_version`、各升级 `applied/final`、CLI 输出「代码最新版本：5 / 最终版本：5」、
     新增「恰有一个遗留用户」断言）。仅使用临时测试数据库，不操作真实数据库。

4. **公共知识库共享 + 最小操作审计**
   - WebUI（`knowledge_base.py`）：页面顶部新增「公共知识库为全局共享资源，修改/删除/重建
     影响所有用户」提示；对「删除文件」「重建知识库」「删除知识库」三个高风险操作加入
     二次确认（两按钮确认/取消，会话状态保存目标）。
   - 后端（`kb_api.py` / `kb_doc_api.py`）：对公共知识库的变更操作（创建/删除知识库、
     上传/删除文档、更新文档、重建索引）统一加认证依赖 `require_password_changed`，
     操作者恒取自服务端认证上下文（不接受客户端指定），并记录最小审计
     `KB操作审计: 操作者=<username>, 操作=<op>, 知识库=<kb>, 详情=<detail>`。
   - 公共知识库保持全局共享：不引入 `owner_id`/ACL，不移目录、不重建向量索引；
     读取类接口（列表/搜索/下载）不受影响。

5. **测试**
   - 新增 `tests/unit_tests/test_temp_file_isolation.py`（13 例，离线、临时 SQLite/目录，
     模型/向量用桩）：临时文件 A/B 隔离、未登录 401、必须改密 403、`/v1/files` 图片
     A/B 隔离、未登录/过期/禁用/伪造签名一律拒绝、客户端不能指定 owner。
   - 新增 `tests/unit_tests/test_knowledge_base_shared.py`（5 例，离线、临时 SQLite、
     KB 服务用桩）：知识库变更接口未登录 401 / 必须改密 403 / 成功后记录审计（操作者取自
     服务端上下文）；公共知识库 A、B 均可操作（无 owner/ACL）；审计格式校验。
   - 更新 `tests/unit_tests/test_db_migrate.py`：内置迁移注册表现为 5 个版本
     （`legacy_conversation_owner` 为第 5 版），相应断言由 4 版改为 5 版。

  `must_change_password=1`），仅供存量会话归属；如未来需要更细粒度归属，
  需追加新迁移版本，不修改已发布的 v5。
