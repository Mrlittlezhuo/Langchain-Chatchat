## 3. 背景

任务 002 已完成后端用户、登录令牌和统一认证依赖，但 conversation 仍没有
owner，消息查询和反馈仍只按 ID 操作，主聊天接口也没有验证当前用户。

附件隔离、公共知识库界面和旧会话 `legacy-admin` 迁移均不在本任务内。

## 7. 设计约束

### 7.1 v3 迁移与模型

- 只在已发布的 v1、v2 后追加 v3；
- conversation 增加 `owner_id VARCHAR(32)` 和 `update_time TIMESTAMP`；
- `update_time` 对旧行回填为 `create_time`，无值时使用当前时间；
- 创建 `(owner_id, update_time)` 联合索引；
- 为兼容尚未执行的存量数据迁移，v3 阶段允许旧行 `owner_id` 为 NULL；
- 所有新建会话必须由服务端写入当前用户 ID，不能由客户端指定 owner；
- 不改动旧 conversation/message 内容和数量；
- 后续存量迁移任务负责把旧会话归属 `legacy-admin`，再收紧非空约束。

### 7.2 会话 API

新增并注册独立 Router：

```text
GET    /conversations
POST   /conversations
GET    /conversations/{conversation_id}
PATCH  /conversations/{conversation_id}
DELETE /conversations/{conversation_id}
GET    /conversations/{conversation_id}/messages
```

要求：

- 全部接口使用 `require_password_changed`；
- 创建请求只接收 `name`、`chat_type` 等业务字段，owner 来自当前用户；
- 列表只返回当前用户会话，按 `update_time DESC`；
- 详情、重命名、删除和历史读取同时过滤 `id + owner_id`；
- 访问不存在、owner 为 NULL 或其他用户的会话统一返回 404；
- 历史消息按 `create_time ASC` 返回；
- 删除会话时同步删除其 message，不能影响其他会话；
- 响应包含 WebUI 后续接入所需的 id、name、chat_type、create_time、
  update_time；owner_id 不必返回。

### 7.3 Repository 与活动时间

- 会话 Repository 提供显式 owner-aware 的 create/list/get/update/delete；
- 消息的读取、创建、回答更新和反馈都必须通过所属 conversation 验证 owner；
- 不再在受保护链路中调用只按 message_id 或 conversation_id 修改数据的函数；
- 新增消息、完成回答或重命名时更新 conversation.update_time；
- 核心函数支持显式 SQLAlchemy Session，测试不得连接真实数据库；
- 保持现有调用方需要的最小兼容性，但不能保留可被新路由绕过的未校验路径。

### 7.4 主聊天和反馈

- `/chat/chat/completions` 与 `/chat/feedback` 使用
  `require_password_changed` 获取当前用户；
- 主聊天请求带 conversation_id 时，必须先验证它属于当前用户；
- conversation_id 缺失时，可为当前用户创建默认会话，并在响应数据中保留
  可供客户端取得的会话 ID；
- 传入其他用户、旧 owner=NULL 或不存在的 conversation_id 时返回 404，且
  不调用模型、不写消息；
- 流式/Agent 内部只传递已经验证的 `owner_id` 与 conversation_id，新增和
  更新消息使用同一 owner；
- 反馈只能修改当前用户会话中的 message，其他用户或不存在的 message
  统一返回 404；
- 本任务不改 `/chat/file_chat` 的临时文件归属，也不重构知识库接口。
