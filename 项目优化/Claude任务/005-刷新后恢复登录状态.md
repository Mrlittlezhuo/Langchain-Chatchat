## 3. 背景

当前 WebUI 将访问 Token 只保存在 `st.session_state`。Streamlit 页面完整刷新
会建立新的 WebSocket 会话并丢失 Session State，因此用户即使 Token 仍有效，
刷新页面后也会回到登录页。

本任务使用浏览器 Cookie 保存短期访问 Token。刷新后从 Cookie 恢复 Token，
并继续调用 `/auth/me` 验证。它只解决登录恢复，不延长后端 Token 有效期，
也不新增 refresh token 或服务端登录会话表。

## 4. 目标

1. 登录成功后将短期 Token 写入浏览器 Cookie；
2. 页面刷新且 Token 仍有效时自动恢复登录；
3. Token 过期、用户禁用、改密或退出时删除 Cookie 并回到登录页；
4. 保持现有强制改密、会话隔离和历史恢复行为；
5. 用离线测试覆盖 Cookie 写入、恢复和清理状态机。

## 7. 设计约束

### 7.1 Cookie 组件

- 优先使用与 Streamlit 1.34 兼容的 `extra-streamlit-components` CookieManager；
- 将依赖加入 Poetry 的 WebUI 依赖区，不改其他版本；
- Cookie 名使用项目专用固定名称，避免与其他应用冲突；
- Cookie 生命周期不超过登录响应的 `expires_in`；
- Cookie 只保存访问 Token，用户信息仍通过 `/auth/me` 获取；
- 将具体 CookieManager 调用封装在小模块中，业务页面不要散落组件细节。

### 7.2 登录恢复流程

页面初始化顺序：

1. 优先读取当前 `st.session_state` Token；
2. Session State 无 Token 时尝试读取 Cookie；
3. 读到 Cookie 后写入 Session State，并调用现有 `ensure_authenticated`；
4. `/auth/me` 成功才进入业务页面；
5. `/auth/me` 失败则同时清除 Cookie 和私有 Session State，显示登录页。

登录成功时同时更新 Session State 和 Cookie。强制改密成功、主动退出及认证
失效时，同时清除两处状态。Cookie 组件尚未 ready 时不能把用户误判为未登录；
应等待组件可用或做一次受控 rerun。

### 7.3 兼容性

- 普通 Streamlit rerun 不重复创建无意义 Cookie；
- 浏览器完整刷新后，只要后端 Token 未过期，应自动进入原用户页面；
- Token 过期后刷新，应显示登录页而不是循环刷新；
- Cookie 不可用时允许退化为当前 Session State 行为，并给出可理解提示；
- 不改变现有会话列表、历史消息和 A/B 用户隔离逻辑。

### 关键设计选择

- **适配层隔离**：所有 CookieManager 细节集中在 `cookie_state.py`，业务页面只调用
  `make_cookie_manager / resolve_login_token / save_token_cookie / sync_token_cookie`。
  组件构造与各函数的 `manager` 参数可注入，便于离线 fake。
- **固定 Cookie 名** `chatchat_auth_token`，避免与其他应用冲突。
- **Cookie 只存访问 Token**：绝不写入用户名、密码或完整用户对象；用户信息仍通过
  `/auth/me`（`ensure_authenticated`）获取。
- **生命周期 ≤ `expires_in`**：`_cookie_max_age` 取登录响应的 `expires_in`，缺失/非法时
  退到 60s 安全上限。
- **初始化顺序**（7.2）：Session State Token 优先 → 无 Token 读 Cookie 恢复并写回 Session
  State → `ensure_authenticated`（GET `/auth/me`）校验 → 成功进入业务页 / 失败清 Cookie
  与私有状态、回到登录页。
- **防无限 rerun**（7.3）：`COOKIE_RESTORE_RETRY_KEY` 一次性守卫，组件未 ready 时只重跑
  一次；仍不可用时给出可理解的降级提示（本会话登录，刷新需重登）。
- **防旧 Token 复活**：退出/改密成功置 `COOKIE_INVALIDATED_KEY`，在 Cookie 真正删除前阻止
  恢复；Cookie 确认为空后自动解除该标记。
- **幂等同步**：`COOKIE_SAVED_TOKEN_KEY/COOKIE_SAVED_EXPIRES_IN_KEY` 标记保证普通 rerun
  不重复写无意义 Cookie。
- **优雅降级**：组件未安装（本机即如此）时 `make_cookie_manager()` 返回 None，整体退化为
  现有 Session State 行为并提示，不抛异常、不破坏原有隔离。
