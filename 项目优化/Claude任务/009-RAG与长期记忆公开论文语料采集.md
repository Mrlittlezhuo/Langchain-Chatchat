## 3. 背景

项目后续需要验证 RAG 入库、检索、引用和长期记忆效果，目前缺少一批来源清晰、
可重复采集、可以合法保存于本地的实验文档。本任务以 RAG、知识库构建、Agent 和
大模型长期记忆为主题，收集开放获取论文及其可追溯元数据，供用户后续手动构建测试知识库。

## 4. 目标

1. 采集 20–30 份有代表性的开放获取论文 PDF，覆盖 RAG 基础、检索/重排、高级 RAG、Agent 和长期记忆。
2. 生成结构化清单，每份论文可追溯到公开来源，并附有中文摘要、主题标签和本地文件校验值。
3. 提供一个可重复执行的轻量采集/校验脚本，支持断点跳过、去重和失败记录。
4. 产出可直接用于 Langchain-Chatchat 知识库上传的本地文档目录，但不自动上传或修改真实知识库。

## 5. 允许修改范围

- `knowledge-corpus/rag-memory/`：采集脚本、README、清单、失败记录和本地文档目录；
- `knowledge-corpus/rag-memory/documents/`：下载的开放获取 PDF，作为本机数据产物；
- 本任务文档末尾的“Claude 执行报告”。

如需在该目录内增加 `.gitignore`，可忽略 PDF 和临时下载文件，但 README、脚本和结构化清单应保留为可审查文本。

## 6. 禁止事项

- 不修改 `libs/`、`chatchat-study-data/`、数据库、日志、配置、向量索引和启动脚本；
- 不调用项目 API 创建知识库，不执行上传、向量化或重建知识库；
- 不抓取需要登录、付费、绕过访问限制或明确禁止自动访问的内容；
- 不伪造论文元数据、许可信息、摘要、下载结果或测试结果；
- 不把搜索结果页、未核对的第三方转载页当作论文原始来源；
- 不安装新依赖；优先使用 Python 标准库或环境已安装的 `requests`；
- 不执行 `git commit`、`git push`、`git reset`、`git checkout`、`git clean` 或 `git stash`。

## 7. 数据与来源约束

- 优先使用 arXiv、OpenReview、ACL Anthology 或作者/研究机构官方公开页面；
- 每条记录至少包含：唯一 ID、标题、作者、年份、主题、来源页 URL、PDF URL、访问/许可说明、本地路径、SHA-256、语言、关键词和中文概要；
- 清单使用 UTF-8 的 JSONL 或 CSV，字段稳定，后续可用脚本读取；
- 按论文 ID、DOI/公开编号和 SHA-256 去重；
- PDF 必须能被识别为 PDF、大小非零，损坏或 HTML 伪装文件不纳入成功清单；
- 建议语料总量不超过 300 MB，不为凑数量收集低相关文档。

可从 RAG、DPR/Contriever、FiD、HyDE、Self-RAG、CRAG、RAPTOR、GraphRAG、ReAct、MemGPT、
Generative Agents、LongMem、MemoryBank、HippoRAG 等方向选取有代表性工作，但允许根据公开可用性调整具体清单。

## 8. 实现任务

1. 建立语料目录和 README，说明主题范围、目录结构、采集方法、再次执行方式及后续手动入库步骤。
2. 搜索并核对候选论文，确认原始来源与公开 PDF 后写入种子或结构化清单。
3. 编写轻量脚本，根据清单下载、跳过已存在文件、计算校验值、检查 PDF 并记录失败项。
4. 执行实际采集，生成最终清单和统计，抽查标题、文件与元数据是否一致。
5. 在 README 中记录哪些文档适合分别测试检索、多文档综合、引用和长期记忆，并给出 8–12 个建议验收问题。
