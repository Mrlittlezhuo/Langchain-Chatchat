# 第一轮优化方案

## 1. 目标

第一轮优化的目标是让 Langchain-Chatchat 从“熟悉模型和配置文件的开发者才能安全使用”提升到“多人可以在私有环境中独立登录、管理自己的资料并获得可验证回答”。

完成后，用户应当能够：

1. 使用自己的账户登录和退出；
2. 只看到自己的会话、知识库、文件、上传任务和连接器；
3. 在页面完成模型连接检查和首次知识库创建；
4. 清楚看到文件解析、分块、向量化、完成或失败状态；
5. 从回答中的引用跳转到具体文件和片段；
6. 在模型、Embedding、向量库或工具出错时获得可执行的恢复建议；
7. 停止生成、重试回答，并在危险工具执行前确认。

## 2. 当前问题与用户影响

| 领域 | 当前情况 | 用户影响 | 优先级 |
|---|---|---|---|
| 身份认证 | FastAPI 路由没有统一认证依赖 | 任何可访问服务的人都可能调用业务接口 | P0 |
| 会话隔离 | `conversation` 和 `message` 没有用户归属 | 知道会话 ID 后存在越权读取或修改风险 | P0 |
| 知识库隔离 | 知识库使用全局 `kb_name`，文件路径未按用户隔离 | 不同用户可能重名或访问彼此文件与检索结果 | P0 |
| MCP 隔离 | 连接器名称全局唯一，环境变量直接存储 | 用户之间可能看到或覆盖连接配置及凭据 | P0 |
| 媒体访问 | `/media` 直接挂载为静态目录 | 私有文件无法进行逐项授权 | P0 |
| 首次使用 | 需要外部模型服务、命令行初始化和 YAML 配置 | 新用户难以完成第一次可用问答 | P1 |
| 文件入库 | 同步等待，以 toast 和简单进度反馈为主 | 用户不知道文件卡在哪一步，也难以重试 | P1 |
| RAG 可信度 | 分数语义不统一，引用信息不足 | 用户无法确认回答是否来自正确材料 | P1 |
| 错误恢复 | 部分错误提示仍引用旧的 `api.py`、FastChat 和 Wiki | 用户无法根据提示恢复服务 | P1 |
| Agent 可控性 | 工具过程偏技术化，高风险操作缺少统一确认 | 用户不清楚 Agent 正在做什么 | P2 |

## 3. 第一轮范围

### 3.1 P0：用户体系与资源隔离

详细设计见[用户体系与数据隔离设计](./用户体系与数据隔离设计.md)。第一轮必须完成：

- 管理员初始化、用户创建、禁用、启用、重置密码；
- 用户登录、退出、修改密码和会话失效；
- WebUI 登录页和当前用户菜单；
- FastAPI 统一认证依赖；
- SDK 使用的个人 API Key；
- 会话、消息、知识库、知识文件、文件片段、临时知识库、上传任务和 MCP 配置的用户隔离；
- 用户私有媒体文件的鉴权下载；
- Agent 工具只能访问当前用户授权的资源；
- 存量数据迁移到遗留管理员账户；
- 登录、用户管理、权限拒绝和敏感操作审计日志；
- 用户 A 无法通过猜测或替换 ID 访问用户 B 的任何资源。

### 3.2 P1：系统状态与首次配置

新增一个面向用户的系统状态和首次运行入口，至少展示：

```text
API 服务             正常 / 异常
默认 LLM             正常 / 异常
默认 Embedding       正常 / 异常
Reranker             正常 / 未配置 / 异常
数据库                正常 / 异常
向量库                正常 / 异常
```

要求：

- 首次登录可以完成模型平台、地址、密钥、模型名称的配置和连接测试；
- 私密密钥写入安全配置，不在 UI、日志和普通配置查询接口中明文回显；
- 每项异常都给出“问题、可能原因、下一步操作”；
- 保留 YAML 高级配置能力，但普通用户不依赖编辑 YAML 才能开始使用；
- 更新 README、页面截图和故障排查说明，删除过时的 FastChat/API 提示。

### 3.3 P1：知识库上传任务化

把文件处理从一次同步请求提升为可查看状态的任务：

```text
已接收 -> 解析中 -> 分块中 -> 向量化中 -> 已完成
                                  \-> 失败 -> 重试
```

每个文件至少记录：

- 上传用户；
- 所属知识库；
- 文件显示名与服务端存储名；
- 当前阶段；
- 已完成片段数和总片段数；
- 开始、更新时间和结束时间；
- 对用户友好的错误原因；
- 仅供排障使用的错误代码和 trace ID；
- 重试次数和最后一次重试时间。

界面要求：

- 上传后立即出现任务卡片或任务列表；
- 页面刷新后仍能查看任务状态；
- 单个文件失败不影响其他文件；
- 支持失败重试和取消未开始任务；
- 默认隐藏分块长度、重叠长度、向量库类型等高级参数；
- 删除文件、重建索引和删除知识库必须二次确认。

第一轮可以采用数据库任务表加受控后台 worker，不强制引入 Redis；当单机 worker 无法满足吞吐量时再独立引入任务队列。

### 3.4 P1：RAG 可信回答

第一轮必须先修正检索结果协议，再调整界面：

```text
RetrievalHit
  document_id
  chunk_id
  knowledge_base_id
  file_id
  content
  source_name
  page_or_section
  retriever
  raw_score
  normalized_score
  rank
  fusion_score
  rerank_score
```

要求：

- 所有检索器明确分数方向，统一输出“越大越相关”的归一化分数；
- 不再使用默认 `3.0` 充当实际检索分数；
- 阈值在融合或重排后的统一阶段执行；
- BM25 和向量检索遵循同一输出协议；
- 用户查询只检索当前用户拥有的知识库；
- 模型上下文包含稳定的来源编号、文件名和片段定位信息；
- 回答正文使用 `[1]`、`[2]` 形式引用；
- 点击来源可查看原文片段，但仍需检查当前用户权限；
- 没有足够证据时明确拒答，或明确标注“以下为模型通用知识”；
- 恢复点赞、点踩和问题原因反馈，并关联用户、回答、引用与检索 trace。

### 3.5 P1：错误恢复与安全操作

统一用户错误结构：

```json
{
  "code": "MODEL_SERVICE_UNREACHABLE",
  "message": "无法连接默认模型 qwen2.5-7b",
  "suggestion": "请启动模型服务，或前往模型设置修改服务地址",
  "trace_id": "..."
}
```

要求：

- 页面显示简明问题和恢复按钮，技术详情折叠展示；
- 不直接把 `e.body`、堆栈、密钥或环境变量显示给普通用户；
- 模型生成支持停止和重新生成；
- 删除知识库、删除文件、重建向量库、执行 Shell 和外部写操作必须确认；
- 未授权资源统一返回不泄露资源存在性的响应；
- API 和 WebUI 错误使用同一错误码表。

### 3.6 P2：聊天和 Agent 体验收敛

导航按用户任务组织：

```text
新对话
历史记录
知识库
设置
```

“新对话”中选择普通问答、知识库问答、临时文件问答或 Agent。MCP 管理移动到“设置 -> 连接器”。

Agent 要求：

- 展示自然语言阶段，如“正在检索资料”“正在调用计算工具”；
- 原始工具参数与 JSON 输出默认折叠；
- 工具执行具有最大步骤数、单步超时和总超时；
- 用户可以停止当前运行；
- Shell、文件写入、外部系统写入等高风险操作执行前确认；
- 所有工具从认证上下文获得用户身份，不能由模型自行指定 `user_id`；
- MCP 凭据不进入模型上下文、前端响应和普通日志。

## 4. 建议实施顺序

### 阶段 A：迁移能力和认证骨架

1. 引入正式数据库迁移机制；
2. 增加用户、登录会话、API Key 和审计日志模型；
3. 增加认证路由与 `get_current_principal` 依赖；
4. 支持关闭认证的本地兼容模式，但网络部署默认开启认证；
5. 完成登录页、退出和当前用户展示。

### 阶段 B：全资源隔离

1. 会话和消息；
2. 知识库、文件、片段和向量检索；
3. 临时文件和媒体下载；
4. MCP 配置、环境变量和工具执行；
5. 管理员用户管理页面；
6. 全量越权测试。

在阶段 B 完成前，不应将服务开放给多个互不信任的用户。

### 阶段 C：用户完成任务的可见性

1. 系统状态页；
2. 首次配置向导；
3. 上传任务状态、失败和重试；
4. 可操作的统一错误提示；
5. 删除确认和运行取消。

### 阶段 D：RAG 可信度

1. 检索分数协议和回归测试；
2. 用户范围内的混合检索；
3. 引用上下文和来源查看；
4. 无答案边界；
5. 用户反馈和离线评测集。

### 阶段 E：体验验收

1. 两个普通用户和一个管理员的端到端测试；
2. 桌面端主要任务走查；
3. 键盘操作、焦点、标签和对比度检查；
4. 更新安装、管理员、普通用户和升级迁移文档；
5. 完成自动化测试和回滚演练。

## 5. 第一轮完成标准

### 5.1 用户与隔离

- 用户未登录时不能访问任何私有业务接口；
- 用户 A 不能读取、搜索、修改、删除或下载用户 B 的资源；
- 修改 URL、请求体中的资源 ID 或会话 ID 无法绕过授权；
- 管理员可以创建、禁用、启用用户和重置密码；
- 被禁用用户的已有会话和 API Key 立即或在明确的短时窗口内失效；
- 审计日志能够回答“谁在什么时候对什么资源做了什么”。

### 5.2 用户任务

- 新用户不改代码即可完成模型连接检查；
- 用户可以创建知识库、上传文件并持续查看处理状态；
- 任一失败文件都提供原因、trace ID 和重试入口；
- 每个知识库回答都有可查看来源，或明确说明无可靠依据；
- 用户可以停止生成、重新生成、复制、反馈和导出回答；
- 危险操作都有明确对象、影响范围和二次确认。

### 5.3 工程质量

- 数据库迁移支持升级和回滚；
- PR/Push 自动运行认证、隔离、API 契约和最小 RAG 回归测试；
- 日志不包含密码、访问令牌、API Key、MCP 环境变量或文档原文；
- README 和页面截图与当前版本一致；
- 单用户旧数据迁移后数量一致，并可以正常检索和对话。

## 6. 第一轮非目标

以下内容不进入第一轮，避免范围失控：

- 公开自助注册、短信或邮件验证码；
- 复杂组织、团队、部门和知识库分享；
- 计费、额度购买和商业化后台；
- FastGPT 式可视化工作流编辑器；
- 一次性替换 Streamlit 前端；
- 一次性升级全部 LangChain 依赖；
- 大规模 Kubernetes、多区域和高可用架构；
- 用户行为推荐、内容运营和社交功能。

团队空间和知识库共享应在第一轮严格隔离稳定后再设计，不能通过放宽查询条件临时实现。

## 7. 需要持续观测的指标

| 指标 | 目的 |
|---|---|
| 登录成功率和失败原因 | 发现账户、密码和会话问题 |
| 首次登录到首次成功问答耗时 | 衡量上手成本 |
| 文件入库成功率及各阶段耗时 | 定位解析和向量化瓶颈 |
| RAG 无结果率、Recall@K、引用点击率 | 衡量检索质量与用户信任 |
| 回答点赞率、点踩原因 | 建立真实质量反馈 |
| 越权拒绝次数 | 发现攻击或客户端缺陷 |
| Agent 取消率、超时率、工具失败率 | 改善 Agent 可控性 |

指标按用户汇总时应避免记录用户原始问题和文档正文，必要内容需脱敏或取得明确授权。
