# Langchain-Chatchat 项目优化

本目录记录项目优化方案。当前第一轮采用最小改动策略，只解决用户身份和聊天历史隔离，不把知识库、模型、工具和 MCP 改造成用户私有资源。

## 第一轮准确范围

### 用户私有

- 每个人自己的聊天框；
- 会话列表、会话名称和会话状态；
- 每个会话中的消息历史；
- 回答反馈；
- 临时文件对话和聊天附件，因为它们属于聊天内容。

### 全体登录用户共享

- 知识库列表；
- 知识库文件和向量索引；
- 知识库上传、编辑、删除和重建能力；
- 模型配置；
- 系统工具和 MCP 配置。

所有已登录用户都可以上传和编辑公共知识库内容。第一轮不引入知识库所有者、团队空间、资源 ACL 或向量库用户隔离。

## 第一轮要解决的问题

1. 增加最小用户登录和管理员账户管理；
2. 给 `conversation` 增加用户归属；
3. 消息通过所属会话继承用户边界；
4. 会话列表和历史记录从后端持久化加载，不再只依赖 Streamlit 会话内存；
5. 用户 A 无法读取、修改、删除用户 B 的会话和消息；
6. 用户 A 和用户 B 可以共同使用并编辑同一个知识库；
7. 旧会话统一迁移到一个遗留管理员账户；
8. 增加最小的认证、会话越权和共享知识库回归测试。

## 暂不进入第一轮

- 知识库用户隔离；
- 知识库分享和团队空间；
- MCP、模型和工具的用户隔离；
- 个人 API Key、OIDC、复杂角色和权限矩阵；
- 上传任务队列、完整系统状态中心；
- 可视化工作流；
- 大规模前端改版。

RAG 引用、检索分数、上传状态、错误提示和 Agent 可控性仍然是有效优化方向，但放在聊天隔离稳定后的后续迭代中。

## 核心原则

### 身份来自服务端

当前用户由登录凭据解析，不能相信请求体中的 `user_id`。

### 会话 ID 不是权限

即使会话 ID 是随机 UUID，所有查询、更新和删除仍必须同时满足 `conversation.owner_id == current_user.id`。

### 消息继承会话边界

第一轮不必给每条消息重复增加 `user_id`。读取或修改消息时，通过带用户条件的会话关联完成授权。

### 公共知识库明确共享写入

知识库继续使用现有全局结构。任何已登录用户都可以查看、上传、编辑和删除知识库内容；界面必须提示这些操作会影响所有用户。

### 最小迁移

只迁移用户、会话和必要的聊天附件归属，不移动公共知识库目录，不重建公共向量索引。

## 状态说明

这些文档是实施设计，不代表功能已经完成。只有代码、数据库迁移、WebUI、测试和升级说明全部满足完成定义后，任务才能标记完成。
