# Langchain-Chatchat 项目优化

本目录用于管理当前项目从“开发者工具”向“可供多人稳定使用的私有知识库与 Agent 产品”演进的优化方案。

## 当前判断

项目已经具备普通对话、RAG、知识库管理、Agent、工具调用和 MCP 等主要能力，但当前默认假设是受信任的单用户环境：

- API 没有统一身份认证入口；
- 会话、消息、知识库、文件和 MCP 配置没有用户所有权；
- 只要知道资源标识，就可能访问其他人的数据；
- 知识库以全局名称和磁盘目录组织，不支持可靠的用户隔离；
- WebUI 更接近开发者控制台，首次配置、运行状态、错误恢复和回答可信度仍需完善。

因此，第一轮优化不以增加更多模型、工具或工作流节点为目标，而是优先解决以下问题：

1. 用户身份、登录和会话管理；
2. 对话、知识库、文件、临时文件、MCP 与工具执行的数据隔离；
3. 首次配置和系统健康状态；
4. 知识库上传任务的进度、失败与重试；
5. RAG 分数、引用和无答案边界；
6. 危险操作确认、错误提示和 Agent 执行可控性。

## 第一轮总原则

### 1. 默认拒绝

除登录、健康检查和明确公开的静态资源外，所有业务接口默认要求认证。没有权限时不返回资源内容。

### 2. 身份只能来自服务端

业务接口不接受客户端传入的 `user_id` 作为授权依据。当前用户必须由经过验证的会话、访问令牌或 API Key 解析得到。

### 3. 资源默认私有

第一轮不做复杂的团队空间和知识库分享。每个用户只能访问自己的会话、消息、知识库、文件、上传任务和 MCP 配置。团队协作作为后续阶段单独设计。

### 4. 用户体验优先于参数数量

普通用户只看到完成任务所需的参数。`Top K`、分数阈值、分块重叠、向量库类型等内容放入高级设置，并提供安全默认值。

### 5. 每个回答都可解释

知识库回答必须提供可定位的来源；没有足够证据时必须明确说明，不允许让用户误以为模型自身知识来自知识库。

### 6. 迁移必须可回滚

现有单用户数据迁移给一个明确的遗留管理员账户。数据库、文件目录和向量索引在迁移前备份，迁移失败时可以恢复。

## 状态说明

当前目录保存的是设计与实施计划，尚不代表对应功能已经实现。每个任务只有在代码、迁移、测试、用户界面和文档均满足完成定义后，才能标记为完成。
